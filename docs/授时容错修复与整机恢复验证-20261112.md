# 授时容错修复与整机恢复验证

2026-11-12，Asia/Shanghai。用户授权修复时间容错，并允许下载和整机重启，要求完整恢复流程。当前 PLC 192.168.0.8 运行 native-0.8.1、boot88、配置23、50台/250点。

## 修复

- `NG_PlatformTime.st`：有效时间总误差上限由严格小于1000ms放宽到严格小于5000ms。仍要求1小时内曾成功授时；请求RTT、时基、报文回显和单调时钟连续性检查保留。
- 以 `max(5000ms, 旧锚点累计漂移误差 + 新候选误差)` 判断是否需要再次确认。长时间失联后内部推算的 Anchor 不再冒充已使用UTC下界。
- 超出容差进入可重试状态，10秒后重新确认，不因普通时间偏差进入永久禁止请求的状态。较大回退在误差预算超限时等待平台时间追平，并持续重新授时。
- 保存本boot已输出的最大有效UTC，恢复锚点受此值及已知历史下界约束；有效期间按99.5%～100.5%速率修正，输出不倒退。
- 恢复后仍须依次提交心跳、配置获取，之后才允许数据发送。没有清空队列、绕过ACK/TTL或强制TimeValid。
- `platform_time_test.st`/`NG_PlatformTimeChecks.st`：40项时钟断言，新增48小时未同步后恢复、约2.17秒偏差、有效期间小幅向后修正、90秒回退后持续请求/等待/恢复。原报文断言23项保留。
