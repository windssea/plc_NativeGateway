## 2. 时间接口定稿

### 2.1 Agent 本地 TimeProvider

两种 Agent 提供等价接口，不要求相同语言类名。所有时间判断使用显式快照/令牌，不允许调用者在时间失效时自行回退 RTC。

| 操作 | 固定语义 |
|---|---|
| readMono() | 当前运行期单调毫秒；采集、调度、退避、年龄的同进程经过时间及 uptime 使用它，不跨运行期相减 |
| snapshot() | 返回以下不可变字段；取得快照不刷新同步成功时间 |
| requestSync(reason) | 触发有界测量，不修改 boot/gateway，不占遥测 sequence；不同步阻塞采集线程 |
| validateToken(token, purpose) | 在入队事务提交或 SDK 发送资格判定处检查运行身份、时钟修订和连接/绑定修订；旧任务不能因随后恢复而重新有效 |

快照字段全部存在，允许 null 的位置明确如下：

| 字段 | 类型、单位及范围 |
|---|---|
| bootId | 当前进程/启动 ID；不取 RTC，重载不变、新进程改变 |
| monoMs | 0～9007199254740991 的整数毫秒 |
| utcMs | 可信逻辑 UTC 毫秒；无可信时间为 null，系统兼容模式的未验证时间另行暴露，不占此字段 |
| systemUtcMs | 系统 RTC 的未验证 UTC 整数毫秒，读取失败或不在安全非负范围时为 null；仅用于系统兼容路径/对照显示，不自动提升可信度 |
| uncertaintyMs | 当前保守误差界，非负整数；未知为 null，不以 0 代替未知 |
| source | HUB_MQTT 或 SYSTEM_RTC；后者是显式兼容模式，不获得平台可信声明 |
| state | UNSYNCED、SYNCING、SYNCED、HOLDOVER、EXPIRED、SUSPECT、MAINTENANCE；无效状态仍可返回 monoMs |
| timeValid | 仅 source=HUB_MQTT、state=SYNCED/HOLDOVER、utcMs/uncertaintyMs/syncAgeMs/timeBasisRef 均非 null，且误差预算<1000 ms、同步年龄<3600000 ms、连续性成立时为 true |
| syncAgeMs | 自最后一次成功授时的单调年龄；从未成功为 null；超时/重连不归零 |
| clockRevision | 0～9007199254740991 整数本地任务修订号；失效/离散重建时推进，普通平滑复校不使缓存反复失效 |
| timeBasisRef | 本地配置的现场权威/连续性基准 ID，非 null 时沿用第 2.2 节 ASCII 1～64 字符规则；未知为 null。不等于 boot、session 或 clockRevision，不是服务端签发的 epoch |
| connectionRevision | 0～9007199254740991 整数连接及绑定资格修订号；用于拦截旧连接任务，不进入 DATA |

validateToken 的 purpose 固定如下；身份/绑定撤销均须即时拦截，不由一次时间快照授予长期权限：

| purpose | 平台模式固定判定 |
|---|---|
| CAPTURE | 允许无 UTC 的本地采集；不授予平台入队/发送资格 |
| ENQUEUE | 当前有效时间及任务修订成立；首次接纳还核对事件捕获时的有效 UTC、时钟修订及配置。已接纳历史物化按第 3.2 节核对原所有权/时间证据，不要求旧捕获修订等于当前修订 |
| CONTROL_SEND | 当前连接可用、该 session 已授时、当前有效时间与任务修订成立；允许首次正常 heartbeat/config-get 和真实配置结果应答，不依赖“控制已提交” |
| SEND | DATA 及新诊断发送；在 CONTROL_SEND 的条件外，要求当前 session 正常心跳及 config/get 已依次成功提交 SDK，另检查各自历史/版本/维护资格 |
| ACK_APPLY | 仅核对授权接收连接和既有批次关联，不等待时间有效或控制恢复；旧批次 boot 不必等于当前进程 boot |

time/request 是引导通道，不受 CONTROL_SEND/SEND 限制；连接前的合法 timestamp=null LWT 仍按旧契约。显式系统兼容模式允许 ENQUEUE/CONTROL_SEND/SEND 使用 systemUtcMs 并标记未验证，免去平台复校条件，但保留身份、连接、控制提交及旧业务边界；不得隐式切源。config/epoch/owner 的令牌封装可按语言实现，以上五种判定的观察结果不得改变。

时间有效、MQTT 连接、当前 session 授时通过及控制恢复提交为四个独立条件。新 session 未复校时，旧锚点有效可用于有界采样入队，但 DATA 和带 UTC 控制发送继续关闭。冷启动先订阅授时/配置/ACK，再授时，再正常心跳（无配置时版本 0/WAITING_CONFIG）、config/get，最后按各自资格发送；不得互等 APPLIED、首个新 GOOD 或第一条 STORED。不存在心跳业务 ACK，PUBACK 也不证明 Hub 已接纳。

“控制恢复提交”只记录本 session 中成功交给 SDK 的正常心跳和 config/get；同步拒绝/抛错不算成功，单条 PUBACK 不代替第二条提交。连接/绑定修订改变时撤销该条件；时间失效撤销复校与控制就绪，恢复后重新用当前时间生成并提交控制消息。首次控制经 CONTROL_SEND 可直接发出，因而不与 SEND 构成环形等待。Hub 未接纳或跨队列乱序时仍按 30 秒节奏推进控制，不额外阻塞已经满足本地资格的历史发送。

SYNCING 只表示目前没有可用锚点的测量阶段；正常后台复校期间保留原 SYNCED/HOLDOVER 与预算，不仅因有请求在途就把 TimeValid 变 false。修订号/序号耗尽须受控报错，不允许回绕复用旧令牌；系统兼容模式的 state=UNSYNCED、timeValid=false 并单独标未验证，不伪装平台 SYNCED。

兼容 SYSTEM_RTC 模式保留既有发送路径并标记未验证；其数据不能混入“平台授时已通过”验收，历史入队年龄不能自动升级为可信。NTP 系统时基可供阶段 1 隔离验证，但须有独立测量证据，不能伪造 timeSyncV1 成功。

### 2.2 timeSyncV1 线上字段与边界

Topic 前缀固定 `iot/v1/gateway/{gatewayId}/`；kind 固定 `timeRequest` / `timeResponse`，后缀固定 `time/request` / `time/response`。QoS=1、retain=false，每条含空白的原始 UTF-8 负载最多 2048 字节。Hub 先支持，两类 Agent 自选启用；不更改旧 Header。

| 字段 | request | response | 约束 |
|---|---|---|---|
| schemaVersion | 必填 | 必填 | 整数 1 |
| gatewayId / requestId / bootId / sessionId | 必填 | 原样回显 | ASCII 1～64 字符；首字符字母/数字，其余仅字母/数字/点/下划线/横线 |
| clientMonoMs | 必填 | 原样回显 | 整数 0～9007199254740991，等于保存的 m1 |
| serverReceivedAt / serverSentAt | 不允许 | 必填 | Hub UTC 毫秒，整数 0～9007199254740991 |

除表列字段外全部拒绝；不允许任何字段为 null，不允许 bool 充当整数、浮点形式充当整数、重复键、BOM、非法 UTF-8、NaN/Infinity、额外 timestamp 或超 64 层嵌套。Topic、payload、本地绑定和 broker 必须一致。Hub 只响应未删除、仍归属同一 broker/gateway 的 BOUND 或 UNBINDING 记录；保留 UNBINDING 仅为恢复必要控制/解绑闭环，不增加 DATA 或配置权限。授时不建立在线会话或业务就绪；解绑完成/身份变更后的发送资格须再核验。每部署首版只配置一个授时响应者；不承诺多权威自动切换。

```json
{
  "schemaVersion": 1,
  "gatewayId": "PLC-01",
  "requestId": "time-boot-A-1",
  "bootId": "boot-A",
  "sessionId": "session-A",
  "clientMonoMs": 10000
}
```

```json
{
  "schemaVersion": 1,
  "gatewayId": "PLC-01",
  "requestId": "time-boot-A-1",
  "bootId": "boot-A",
  "sessionId": "session-A",
  "clientMonoMs": 10000,
  "serverReceivedAt": 1792739100000,
  "serverSentAt": 1792739100005
}
```

一次仅有一个待处理请求；新尝试使用新 requestId；处理时须仍属当前未过期请求。同一响应只接纳一次，旧 boot/session、未知请求、回显不一致或可识别 retained 投递不改变时钟。关联不是认证，响应发布权限只能属于 Hub。

固定计算：`rtt=m4-m1`，`processing=t3-t2`，`pathDelay=rtt-processing`，`utcAtM4=t3+max(0,pathDelay)/2`；内部可保留半毫秒，向业务整数毫秒输出时向下取整，并将量化误差计入预算。先做有符号差值检查，不允许 ULINT 下溢。

固定接纳边界：`0<=rtt<2000 ms`，`0<=processing<=500 ms`，`pathDelay>=-50 ms`；负路径延迟容差按 0 计算并计入误差。Hub 同时检查 UTC 耗时与单调耗时，绝对差>50 ms 或任一处理耗时>500 ms 不发布响应；t2/t3 来自同一可注入 UTC Clock，t3 在发送执行器临近 SDK 发布处形成。内部缓冲和网络不对称仍受 RTT/误差预算约束。

数值校验还包括推导值：utcAtM4 及误差区间端点须可用有符号宽类型安全计算，输出 UTC 须处于安全非负整数范围；不能只校验 t2/t3 后允许加法溢出。初始误差界至少覆盖 max(0,pathDelay)/2 的不对称界、负 pathDelay 的容差及量化/采样/排队误差，不能把 RTT/2 或实测偏差直接宣称为完整误差界。

首轮最多 30 秒/10 次，先到者结束，期限处到达的响应不复活已过期请求；首选 3 个候选推进到同一 monoMs 后最大差<=500 ms，选择 pathDelay 最小者。不足 3 个时仅可用 rtt<=500 ms 且与其他有效候选一致的样本启动，10 秒后复校。正常每 300 秒±10% 复校；轮间退避 5/10/20/40/60 秒，错峰后仍硬限 60 秒。误差预算必须覆盖路径不对称界、采样/线程/量化误差、漂移及修正残差；未配置可验证的漂移上界时不能把一小时硬上限当成可用保持时间。

小偏差绝对值<=1000 ms 按 99.5%～100.5% 速率平滑；总预算达 1000 ms 仍要关闭业务门槛。大偏差先 SUSPECT 并关闭新批次及新/旧 DATA 发送，再有界复测；确认回拨且低于历史边界时 MAINTENANCE。正常重启不刷新历史年龄；大幅回拨自动恢复、多权威迁移及停机期间任意调时的连续性证明不属于首版承诺。

requestId 生成必须在使用最大长度 bootId/最大序号时仍满足 64 字符；使用有碰撞防护的独立编码或摘要，不直接无界拼接/截断 bootId。结构错误与来源错误均不回 time/response 错误变体，保持响应八字段不变；设备本地原因固定为 TIMEOUT、INVALID_RESPONSE、STALE_REQUEST、SOURCE_MISMATCH、HIGH_DELAY、INCONSISTENT_SAMPLES、CLOCK_DISCONTINUITY、HOLDOVER_EXPIRED、ROLLBACK_REQUIRES_MAINTENANCE。人类提示可本地化，不能把异常全文或输入凭据塞进协议。

## 3. 采样与报告规则定稿：reportPolicyV1

这是两类升级后 Agent 的目标行为，旧实现仍按原策略运行，不事后追认为通过。内部采样身份固定为 `(gatewayId, captureBootId, sampleSeq)`，sampleSeq 为运行期递增安全整数，按**每个点的一次最终结果/一次状态转换事件**分配；不使用 UTC 去重。配置身份、pointId、nominalPollDueMonoMs、completedMonoMs、原始 UTC、timeValid/clockRevision、kind/value/quality 均随内部记录保留，冻结后不重新缩放。

kind 固定 PHYSICAL_RESULT 或 QUALITY_STATE：一次物理读取的内部重试只形成一个最终结果；同一块读取 N 个点形成 N 个点事件。周期因资源不足被跳过只增加 missedPollCycles，不伪造 N 个 BAD 物理样本。UNKNOWN/STALE 是明确的一次状态转换事件，时间为实际检测时刻，不把旧 GOOD 重新打上当前时间；相同状态每次扫描不重复生成。GOOD 值须有限数或 bool，其他质量 value=null；沿用全部旧质量码，时间可信度与采集质量分开。

PHYSICAL_RESULT 的 nominalPollDueMonoMs 是实际调度槽的名义到期，completedMonoMs 不得早于该槽；QUALITY_STATE 没有物理槽，该字段为 null，completedMonoMs 是检测时刻。每点事件按最终完成/状态检测次序串行决策，同一轮询槽最多一个最终结果；采样 UTC 取本地最终完成/状态检测时刻的 TimeProvider 快照，不用名义槽或 Hub receivedAt 冒充采样时刻，也不直接信任 OPC UA 等源时间戳。时间无效时原始 UTC 为 null，恢复后不得回填。源设备时间可作本地诊断，首版不替代共同采样 UTC。

UNKNOWN 在点启用且尚无最终结果时创建一次；STALE 表示没有新最终物理结果的持续时长达到 staleAfterMs，以最近一次物理结果的 completedMonoMs（从未取得结果时用启用时刻）为单调起点，不按最近 GOOD 起算。达到阈值且当前状态尚非 STALE 时产生一次 QUALITY_STATE；新 BAD/GOOD 最终结果均结束这段无结果状态。持续返回 BAD 时保留真实 BAD，不在每次扫描把它交替改成 STALE。lastGoodTimestamp 单独表示最近可信 GOOD，不替代上述活性计时；同一串行时刻先处理已完成物理结果，再判断陈旧。

### 3.1 选择与基准

先对不可变入口事件作一次资格决策，再进入有界待上报队列；不能等 MQTT 有空位才从 latest 重建历史。HMI/latest 只作视图。对同一个事件的重试不能增加 eligibleEventsTotal 或新增采样身份。

| 触发 | 所有模式的固定规则 |
|---|---|
| FIRST | 当前配置/有效采样代际尚无已接纳基准时，首个最终结果/明确 UNKNOWN 状态可选一次；接纳失败仍记账，下一独立事件可再尝试 |
| QUALITY_CHANGE | 相对有效报告基准的质量变化，在 cyclic/change/change_or_cyclic 都触发，不受 deadband 抑制 |
| VALUE_CHANGE | 仅 change/change_or_cyclic；新旧均为 GOOD 且数值差绝对值严格大于 deadband，或 bool 改变；相等于 deadband 不触发 |
| CYCLIC_DUE | 仅 cyclic/change_or_cyclic；取名义槽达到/超过下一报告截止点的首个物理最终结果，不比较组包完成时刻；QUALITY_STATE 不消费周期槽 |

同一事件符合多个触发也只选一次。每点配置/有效采样代际激活时，用调度器计划的首个名义轮询槽 O 建立报告网格 O+k×reportIntervalMs（k>=0），nextReportDue 初始为 O；不得用首次 UNKNOWN 检测、完成、接纳或落盘时刻移动原点。时间恢复只建立新有效代际的网格，不补失效期间的槽，既有历史仍按旧身份保留。change 不建立周期网格，missedReportSlotsTotal 为 0。

周期物理事件 q=nominalPollDueMonoMs 达到 nextReportDue 时，n=floor((q-nextReportDue)/reportIntervalMs)+1；该真实结果服务最后一个到期槽，前 n-1 个无结果服务的槽增加 missedReportSlotsTotal，然后 nextReportDue 前进 n 个间隔。此推进属于一次资格决策，**不等待接纳成功**：该事件拒绝接纳已属于应报损失，不再把同一槽记成“漏报告槽”。提前 FIRST/质量/值变化和所有 QUALITY_STATE 均不推进截止点。早于截止点且无 FIRST/质量/值变化的事件明确归为 policyFilteredEventsTotal，不算缓冲损失。没有后续物理事件时不按扫描次数增加 missedReportSlots，验收须同时核对 missedPollCycles 和实际入口记录，不能用该计数为 0 证明采集完整。

数值比较使用已经转换好的有限 binary64 工程值，不再次 scale/offset、不暗加 epsilon 或按显示小数位舍入。质量变化等提前报告不移动固定网格原点；同一物理事件已因质量/变化触发选择，后续组包到期不能再为其追加一个周期副本。

因此 poll=report=5000 ms 时，每个正常逻辑轮询周期的最终结果各有一次上报资格，实际读取完成的毫秒级抖动不应随机漏轮；poll 更快时取到期后的首个结果，其余按上述规则过滤；poll 更慢时只报真实新结果及质量状态转换，不循环重发旧 GOOD 快照填满时间轴。无新物理结果时 STALE 状态只发一次，后续新 BAD 结果仍可按周期报告。周期目标不是“每 reportIntervalMs 必有一条不同物理采样”。

固定选择“到期后首个事件”而非“发送线程醒来时的最新值”，这是需要两种 Agent 对齐的目标变化，不是当前 Python latest 合并行为已经满足。聚合窗口 batchIntervalMs 只控制批次物化，不得决定源事件是否被接纳。

基准区分为：已成功接纳且仍有所有者的 pending shadow，和已完成该模式提交边界的 committed baseline。按同一点/配置/有效采样代际的 sampleSeq，取二者中**最新已接纳事件**比较；不能因“shadow 优先”让旧 shadow 遮盖更新的 committed baseline。提交只允许向更新事件推进，SQLite 完成、逆序 STORED 或旧 boot 历史恢复均不回退当前基准。接纳拒绝不推进二者；周期截止点独立按上段推进。已接纳事件终止时撤销对应 shadow，committed baseline 只表示曾完成本地提交而非已送达；清理不能自动复活同一已终止事件。配置/有效代际切换为新采样清理基准，既有历史保持原所有权与计数。

### 3.2 所有权与批次

被选事件只能属于暂存、FIFO、冻结批次或隔离/终止记录中的一个逻辑所有者；journal 中重复表示不多算一次。两种 Agent 均在达到配额前决定接纳/明确拒绝，原生可淘汰最旧、Python 可拒绝新入队，但计数必须精确到事件。不可将一次 enqueue 失败直接等同于一个样本丢失。

“首次逻辑接纳失败”与“后续 SQLite/日志提交尝试失败”分开：事件仍由上游 RAM FIFO 保留时只是 P 和一次尝试失败，不增加终止损失；只有所有者按明确策略放弃并证明未发送时才归 L，无法排除已发送则归 U。达到持久边界前不得标 durable，但也不能因数据库暂时忙就同时将同一事件算为待处理和丢失。

批内只允许一个 gateway/configVersion，同一 deviceId+pointId 最多一个值；同点连续多个应报事件须分不同批，不能再合并覆盖。一个事件冻结后只进入一个 messageId；重试保持完整 payload、顺序和哈希，不改 bootId/sequence/UTC。首轮 30 秒/后续 60 秒 STORED 等待、最多 8 批业务在途；新旧类别 1:1 公平、各自 FIFO，重试计入各端总限速。当前 DATA 仍只传旧字段，内部 sampleSeq/kind 不直接加入线上值。

原生 RAM 接纳是易失承诺；Python SQLite 成功入队事务才是持久批次边界；原生日志以 durableSeq/PREPARE/ACK 为界。历史批次资格不依赖当前启用、最新期望 APPLIED 或新 GOOD，时间失效时入站真实 ACK 继续处理。本地过期、明确拒收、迟到 STORED 及恢复严格按授时文档的终态表执行。

已接纳的 FIFO/暂存事件也属于历史，不能因未持久化就当成可随意清空的 latest：时间失效后保持 P；若因明确容量/年龄/身份策略终止则按 L/I/U 记账。恢复后使用当前有效任务令牌重新物化，保留捕获时有效 UTC、配置、captureBootId/sampleSeq 及历史时基，原捕获 clockRevision 不要求等于当前值。只清理尚未接纳的无效缓存/旧准备任务；不能将无效时采到的事件补时入队，也不能为重试重复接纳同一事件。已冻结批次继续原字节，历史与新有效样本采用不同资格路径。

公平分类以每次 DATA 门槛从关闭变为开放时的接纳水位划分：水位及以前仍待处理项属历史，之后新接纳项属新数据；恢复库全部为历史。类别在该轮不随 attempts 改变，重试保留类别；再次恢复可建立新水位但不重置退避/限速。新物化批次不混合两类事件，已冻结原批次整体归类而不拆改。1:1 指双方均有可发送项时交替选择批次尝试；类内选最早可发送项，等待退避/确认的项不阻塞其后可发送项，不承诺 ACK 完成顺序。FIFO 物化、批次槽和发送信用均须留出新数据推进机会；容量淘汰仍按既定策略精确记账，不以公平调度掩盖拒绝新接纳。

## 4. 缺口与计数定稿

### 4.1 事件、尝试及快照不能混算

`counterEpoch` 固定为当前 bootId。下表所有 Total 是该运行期的累计事实，每个事件/尝试按定义至多增加一次；重连、配置变化、时间复校不归零。新进程开启新 epoch，Hub 不跨 epoch 相减；旧 SQLite dropped/dead_pruned 的跨进程总数保留为 legacy 本地统计，不直接填入新 Total。达到安全整数上限时饱和并设置 counterOverflow=true，不回绕；此时完整计数验收失败。

| 字段 | 单位及增加条件 |
|---|---|
| capturedEventsTotal | 点事件；每个 PHYSICAL_RESULT/QUALITY_STATE 创建一次 |
| eligibleEventsTotal | 点事件；资格选择为应报，包括随后因无效时间/配额失败不能接纳的事件 |
| policyFilteredEventsTotal | 点事件；不满足报告触发而有意过滤，不是丢失 |
| timeInvalidEventsTotal | 已选点事件；缺少可信 UTC 而不能接纳的事件，归已知未发送损失；原始质量不改成 BAD |
| captureOverflowEventsTotal | 点事件；有界入口失败且能精确归属的事件，不由扫描次数估算 |
| undecidedLostEventsTotal | 点事件；事件在资格判断前丢失、无法证明是否应报；不猜测其 eligible 数，完整性标记为 false |
| knownUnsentEventsTotal | 已选点事件；证明从未提交 SDK 就因时间、入口、容量、年龄、身份等终止 |
| isolatedEventsTotal | 已选点事件；明确永久拒收/隔离时首次归类；死信随后修剪不重复增加 |
| uncertainDeliveryEventsTotal | 已选点事件；曾提交 SDK 或无法排除已交付，但本地必须终止保留/重试时首次归类 |
| storedConfirmedEventsTotal | 已选点事件；由可核验真实 STORED 首次确认；同一批 ACK 重复不增加 |
| lateStoredEventsTotal | 点事件；已在本地终止后，经仍可核验关联得到迟到 STORED；是 storedConfirmed 的子集，不另外相加 |
| enqueueRejectedAttemptsTotal | 尝试；一次实际原子入队尝试被拒绝加 1，不是损失点数；反复重试不得重复增加同一事件的损失计数 |
| missedPollCyclesTotal | 逻辑点轮询周期；已启用且应执行但未执行的槽，每点每槽一次；块内 N 个点跳过一轮计 N，内部读取重试不计，停用/尚未生效期间不计 |
| missedReportSlotsTotal | 点的名义报告槽；按第 3.1 节 n-1 精确增加，不等于丢样个数；change 为 0，状态事件和接纳失败不重复加槽 |
| sourceTimestampRepeatEventsTotal | 同一点/捕获 boot 的相邻 PHYSICAL_RESULT 均有原始 UTC 且相等；计量粒度诊断，不据此去重或判丢失；null 与 null 不算相同 UTC |
| gapRecordsTotal | 缺口明细创建次数，不是点数；明细合并/截断不减累计值 |

资格判断必须独立于下游 SDK/数据库阻塞推进；若确有资格前溢出，记录 undecidedLost 并中止“完整历史通过”声明，不能把它藏在 policyFiltered。选中但时间无效时只计 timeInvalid 和对应 knownUnsent，不重复添加两个终态。质量码变化和恢复首值仍按第 3 节选择。

Total 描述“曾发生过”，**不能直接相加作互斥对账**：同一事件曾交付不确定后得到真实 STORED，会出现在 uncertainDeliveryEventsTotal 和 storedConfirmedEventsTotal 中。对账集合则按当前可核验证据分类：

`应报事件 E = 已证实保存 S ⊎ 仍待处理 P ⊎ 已知未发送损失 L ⊎ 明确拒绝/隔离 I ⊎ 交付结果不确定 U`。

Hub/验收器证实保存优先归 S，即使设备仍在重试，也不重复归 P/U；迟到确认使对应 U（包括交付不确定的本地过期记录）→ S，不能改写历史 Total。明确 Hub 永久拒收与 STORED 冲突则隔离核查，不自行改判。按 captureBoot/config/point/事件身份核对集合，不能把当前 boot Total 与跨 boot 恢复队列直接代入公式。

`captured = eligible + policyFiltered + decisionPending + undecidedLost` 只在同一捕获 cohort、完成资格流水记录后核对；decisionPending 是待决定快照量，不是 Total。资格前溢出须先分配身份/记录 created 事实并计 captured 和 undecidedLost；若连创建数量也无法证明则明确 unknown，不能拿不完整分母做等式。raw 已损坏、身份缺失或旧批次无法建立采样关联时，accountingComplete=false；未知 gauge/缺口数量用 null。16 项 Total 始终为已知事实的非负累计下界，不允许 null，也不把未知损失填成已知零；accountingComplete=false 时禁止以这些数值声称全量完整，该标记在当前 counterEpoch 内不自行恢复为 true。故障窗口的“无损”要求完整证据、L/I/U、undecidedLost 和时间无效未报均为 0，且 P 在排空后为 0、E 与 S 的关联多重集一致。

### 4.2 缺口记录

reason 固定为 CAPACITY_EVICTION、AGE_EXPIRED、CAPTURE_OVERFLOW、TIME_INVALID、VERSION_DISCARD、PERMANENT_REJECT、STORAGE_ERROR、IDENTITY_CHANGE、VOLATILE_RESTART。每条记录携带 gapId、reason、outcome、eventCount 或 null、captureBootId 或 null、configVersion 或 null、点位范围、sampleSeq 范围、UTC 起止或 null。outcome 只取 KNOWN_UNSENT、ISOLATED、UNCERTAIN；未被选中的策略过滤不是缺口。

范围只是索引范围，不表示其中每一个序号/时刻都丢失；eventCount 必须来自实际事件关联。任一精确信息不可得时 null 并标记明细不完整；未知 UTC 不填当前时间。相邻同原因/归属的记录可合并，但必须保留精确数量或明确 unknown，不能把首尾范围宽度当数量。

原生本地明细最多 64 条，线上的 lastGap 只发最后一条摘要；截断设置 detailTruncated 并保留已知累计计数。Python 可用持久明细，但同样固定数量/字节配额。RAM 整机重启后若没有可证明的旧接纳记录，不猜测易失损失数量：记录 VOLATILE_RESTART/UNCERTAIN、数量未知，不能回报零损失。持久日志或 SQLite 也不保证尚未提交的 RAM 样本恢复。

### 4.3 旧 heartbeat.queue 保持兼容

旧字段的 JSON 结构和各已部署实现的统计语义均不静默改变。batches/payloadBytes 仍描述已有物化队列，不代表采样 FIFO 总量；原生包括未清除的 DEAD 槽，Python 当前包括 PENDING+DEAD。

`droppedBatches` **现有含义存在差异**：Python 来自 Outbox 拒绝入队次数，原生来自 Dropped 分支且未覆盖“满队列导致从未组包”的采样。Hub 不能横向相加、换算样本或以其为零证明完整。新统一口径放在下面独立诊断，不重新解释旧报文；旧版本展示须标为 legacy。

## 5. 公共 bufferDiagnosticsV1 定稿

新增 kind=`bufferDiagnostics`，Topic=`iot/v1/gateway/{gatewayId}/diagnostics/buffer`，Agent→Hub，QoS=1、retain=false、UTF-8 最多 8192 字节。schemaVersion=1、diagnosticsVersion=1，严格未知字段拒绝；它是待实现的独立扩展，不是现有 event/heartbeat 的自由附加对象。正常每 30 秒一帧，状态/缺口变化可立即发，但每网关最多每 5 秒一帧并合并变化，不形成无限事件队列；没有业务 ACK 或 STORED。

只在平台时间有效且当前 session 完成正常控制提交后发布；时间无效先本地展示，恢复后发新帧携带累计缺口。Hub 校验绑定、归属、非 retired session 和 boot 内递增 diagnosticSequence；只将与已证明当前 session 关联的帧展示为当前诊断，其余不覆盖当前视图。诊断不建立/续期在线会话，不更新 APPLIED，不推动最新值，不作为采样入库。诊断新鲜度用 Hub receivedAt，90 秒未见新帧标陈旧；不得以旧 Total 回退覆盖新值。

顶层必填字段固定为下例，不允许另加字段；id/safe integer 规则同第 2 节。counterEpoch 必须等于 bootId；diagnosticSequence 从 1 递增且独立于遥测 sequence；time 对象只允许 source、state、syncAgeMs、uncertaintyMs，发送时 source=HUB_MQTT、state=SYNCED/HOLDOVER、0<=syncAgeMs<3600000、0<=uncertaintyMs<1000。Hub 同时沿用 -90 秒～+5 秒报文新鲜度门槛。mode 只取 RAM、SQLITE、JOURNALED；durability 只取 VOLATILE、BATCH_PERSISTENT、SAMPLE_PERSISTENT，依次对应上述三模式，未通过文件恢复前不能上报 SAMPLE_PERSISTENT。

buffer 的 pendingEvents/deadEvents 是快照事件数，分别覆盖未终止的暂存/FIFO/冻结批次，以及仍保有的隔离记录；不是批次数，不重复计算日志副本。遇到旧数据缺少事件身份时对应数量允许 null、accountingComplete=false。pendingBatches/deadBatches 是已物化批次数。quotaKind 明确计量边界：RAM=MEMORY_TOTAL，SQLITE=PAYLOAD_TOTAL，JOURNALED=FILE_POOL_TOTAL；usedBytes/maxBytes 只比较同一种配额的实际消耗/启用上限，不能跨模式直接比较百分比。

MEMORY_TOTAL 包括活跃记录与固定元数据/窗口等配额记账；固定池总分配不得超过原生内存预算，未使用槽位不得重复算成活动记录。FILE_POOL_TOTAL 包括文件池、字典、PREPARE/ACK、缺口/tombstone及整理临时空间，原生 RAM 另受 4 MiB 预算。PAYLOAD_TOTAL 是 Python 既有 PENDING+DEAD payload 配额，**不等于 SQLite DB/WAL/索引/元数据的物理字节数**；后者必须另有本地磁盘预留、元数据数量/字节上限和耗尽验收，不把 64 MiB 宣称为总磁盘上限。oldestPendingAgeMs 无可信依据时 null，ageUnknownBatches 单独计数。任何 gauge 非负，不能用负数表示未知。

Python 的暂存/FIFO/StoreWorker RAM 另有数量/字节硬限，PAYLOAD_TOTAL 不涵盖它们，但 pendingEvents 必须涵盖；每个事件所有权只计一次。跨线程获取诊断须使用同一逻辑快照/修订复核，不能拼接转移前 FIFO 数与转移后 Outbox 数而重复计数。Hub 只接纳当前已证明 session 的严格递增 diagnosticSequence，重复/倒序帧不更新 receivedAt 或陈旧计时；同 boot 切 session 不重置序号或 Total。缺口合并/明细截断不撤销曾发生事实，旧 epoch 不与新 epoch 连续画差值。

### 6.2 报告选择黄金样例

假设时间有效、配置已提交、容量充足、每次选中都成功接纳，sampleSeq 按列出的顺序从 1 开始。质量默认 GOOD，kind 默认物理结果，周期截止点按第 3 节固定。

R01 的完成时刻只是计时抖动向量；同一读计划不能并行重复执行同一轮询槽。nominalDue 必须来自实际调度身份，不能根据结果时间倒推以修饰漏轮。错过的物理轮询按 missedPollCycles 记录，不生成应有但未真实采到的数值。

### 6.3 缺口与迟到确认黄金样例

G01：一个 capture cohort 的 E={e1,e2,e3,e4}：e1 有真实 STORED，e2 仍由 FIFO/批次持有，e3 明确未提交 SDK 就因容量终止，e4 已提交 SDK 但本地放弃且结果未知。集合应为 S=1/P=1/L=1/I=0/U=1，总数 4，计数与批次槽位数无关。

G02：e4 后来经原始关联确认 STORED：集合变 S=2/P=1/L=1/I=0/U=0；uncertainDeliveryEventsTotal 仍保留曾增加的 1，lateStoredEventsTotal 增 1。重复同一 ACK 不再增加；tombstone 已修剪则不能凭无关联 ACK 重建事件。e3 若曾由上游 RAM 持有、对 SQLite 多次 enqueue 失败，仍为 P，最终明确放弃才计 knownUnsent 一次；enqueueRejectedAttempts 可大于 knownUnsent。已经终止的同一事件不因重试复活，配置切换清理已经选中的事件须有 VERSION_DISCARD 等明确结果，不能当 policyFiltered。

原生五分钟覆盖的设计门槛为当前 50 点/秒、300 秒中断+60 秒重试余量、25% 余量，即至少 22500 条紧凑记录，并同时满足全子系统 4 MiB。320 点/同周期为 28800 条；二者只是容量下限计算，不是编译/实机已通过。每主周期新增工作预算<=1 ms、主任务不超期/不触发看门狗，须实测；无法满足则明确降低可覆盖承诺，不能降低真实采集频率冒充通过。

Python 不套用原生 4 MiB；五分钟 A08 也必须对其报文前队列和 SQLite/磁盘预算单独预检，Outbox 默认容量不是零丢样证明。排空时间用实际确认速率计算；150 点/秒对应约 150 秒排空 15000 点只是原生方案假设，未达到不得沿用。资源和物理介质数值仍需后续实测，但“未达时如何判定失败”已固定，不阻塞阶段 0 设计定稿。
