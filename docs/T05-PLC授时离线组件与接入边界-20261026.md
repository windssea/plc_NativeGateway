## 生产接线顺序与未完成项

T05 保持 IN_PROGRESS，下一步仍可先离线实现，不等待 P06：

1. 选定运行候选副本，记录其与恢复工程/性能候选的差异；以稳定的本地配置提供 timeMode/timeBasisRef 及实际漂移依据。不能直接改变 `NG_Bootstrap/NG_Durable` 二进制布局而让旧配置文件被隐式重解释。物理操作前仍要处理 J00 恢复前置。
2. `NG_Mqtt` 加入授时订阅及独立有界响应处理；请求 m1 必须位于 `Client.Publish` 的实际 SDK 接受边界，响应 m4 必须位于最早可观察的消息接收边界，包含无法消除的扫描/库延迟误差。当前 Main 的 TxRequest、TxDone 与 m1 不同，不能用 PUBACK 或稍后解析时刻替代。若厂商库/MCP不能暴露所需证据，应明确交维护方修复，不能假定 20 ms 扫描等于真实接收时间。
3. 生产 Main 在无有效心跳前发 time/request；当前 session 授时通过后，以 CONTROL_SEND 按 heartbeat→config/get 的 SDK 接受事实恢复 SEND。ACK/配置接收不被未授时或新 GOOD/APPLIED 条件堵住。未发送的旧控制 payload 失效后重新编码，不能带旧 UTC 直接补发；配置确认保留真实应用结果及有界关联。
4. CAPTURE 传入逻辑时间、timeValid 和 clockRevision，未授时样本只本地展示/记 TIME_INVALID，不补时。ReportPolicy、分片 Builder 的选择与最终接纳分别复核令牌；仅撤销未接纳工作，不删除已接纳历史。ENQUEUE 与 SEND 分开，已知历史补传不依赖当前 enabled/version/新样本。
5. Delivery 的新/旧 DATA 发送使用当前 SEND 资格，重连保留 attempts/单调截止；ACK_APPLY 无授时仍按原哈希验证和释放。RAM 模式的同运行期保留/终态规则维持原规范；不为本次授时偷偷加入文件日志或七天持久年龄承诺。
6. HMI 增加本地模式/状态/误差/年龄/时基及控制资格，保护原配置兼容；重新计算新增组件和全生产候选的资源布局。当前断言工程布局不能替代完整网关预算，也不沿用旧 4170829 B 作为新候选已测值。
7. 对接完整生产候选后再冷编译和执行隔离断言。真实下载/运行/恢复与 T07 在用户解除“暂不刷 PLC”后按 MCP 实际能力、精确操作流程及 J00 前置推进；本轮不执行。P06 的吞吐/扫描性能及长负载保持后置，不以它阻塞上述功能开发，也不在本报告宣称达到 ≤1 ms/≥90 条每秒。
