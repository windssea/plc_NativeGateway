## 1. 本阶段交付边界

阶段 1 先解决“应报事件进入批次前被覆盖”和**同运行期受测 cohort 的完整对账**：入口事件、reportPolicyV1、有界暂存/FIFO、唯一所有权、不可变批次、公平补传、真实缺口与本地诊断。Hub 保证原 v1 接收链路及验收证据可用，Python 保留既有 SQLite 批次持久边界，原生先做 RAM 模式。跨进程仅先回归已有持久批次原字节恢复，新增采样关联与终态元数据未持久化前，不宣称跨重启事件计数完整。

完整 MQTT timeSyncV1、逻辑 UTC 与 SQLite 时间元数据迁移属于阶段 2；原生文件日志及物理断电保证属于阶段 3。阶段 1 就需要预留 TimeProvider/令牌接口和时间失效下的历史所有权规则，不能先散落新的墙钟调用、以后再整体替换。

时间前置有两条路径：

| 现场条件 | 实施与验收顺序 |
|---|---|
| 已有独立证据可核验的共同局域网时间基准 | 可先实施采样缓冲；真实交付使用明确的 SYSTEM_RTC 兼容路径并记录独立时基证据，timeValid 仍不伪装成平台 SYNCED。时间接口/失效竞争可先用注入时钟做隔离测试 |
| 只有 MQTT，设备日期不可信或无共同时间证据 | 先提前实施阶段 2 的最小闭环：Hub 授时响应 → Agent 首次可信 UTC/当前 session 复校 → CONTROL_SEND → DATA 门槛，然后才能进行真实数据完整性联调；不要求提前完成全部持久化迁移 |

当前 NTP 容器 healthy 只证明服务自身健康，不证明 PLC/IoT 已同步或误差已满足目标。本次不向设备探测时钟，也不将现有服务状态作为阶段 1 放行证据。无真实环境时，可以推进实现和隔离测试，实际验收状态保持待执行。

**提前授时不是只提前两个 Topic。**采用 MQTT 路径前，必须同步前移所有必要的时间门槛：有效性/任务令牌、当前 session 控制恢复、单调重试/同进程重连不清退避，以及 Python `enqueue/reserve/acknowledge/关闭 flush` 各入口不得在无效时间下按墙钟过期。旧 created 的可信度、历史时基及未知年龄/终态来源若无法在当前格式安全表达，所需的最小显式存储迁移也必须前移；不能一边启用平台模式，一边让旧 `_expire(time.time())` 仍可能清理队列。此前置未完成，只推进隔离实现，不开放该模式真实 DATA。完整迁移和其余阶段 2 场景可继续后置，必要保护不能后置。

P01 是记录布局与配额门槛，应先于大规模实现固定；如果容量不够，先明确降低覆盖承诺并复核计划，不能降采样频率来通过同一目标。P06 的编译可先完成，真实扫描耗时和控制器余量必须在后续明确授权的设备验收中测量。PLCnext/vPLC 分别记录证据，RAM 不增加掉电持久承诺，不在本阶段实现文件日志。

P02/P03 与 I01～I03 均覆盖配置应用、启停和在途读取竞争：捕获配置身份不可改成后来版本；配置提交、资格决定、首次接纳及任务撤销有可核验顺序。普通版本切换不清已接纳历史，未接纳旧任务不能借恢复重新有效；实际终止用 VERSION_DISCARD/对应原因或明确 undecidedLost 记账，不藏进 policyFiltered。相同配置重复应用/同进程重载不重复创建启动 UNKNOWN 或重置 boot/计数；确有采样代际切换才按共同规范重建新采样基准。

资源预检以实际应报速率 lambda、可关联 STORED 并完成本地确认释放的独立事件速率 mu 计算，重试/重复 ACK 不增加 mu。稳定负载下 mu 必须大于 lambda；在速率稳定且持续可用时，净排空估算为 backlog/(mu-lambda)。还须核算 ACK 中断后的恢复尾部、既有占用、质量突发、同点拆批造成的小批、死信/缺口/字典及临时复制的峰值字节。22500/28800 是规定负载的设计下限，不是任意模式/恢复时长的覆盖保证；Python 的批次数、payload 与 RAM 阶段各自预检，不能用 SQLite 容量替代入口缓冲容量。
