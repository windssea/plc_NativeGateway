## 编码及发布边界

`NG_CaptureEvent`尾部新增`PollSkippedBefore:UDINT`，从源游标的`PollSkippedPending`转移，物理结果捕获后清零；质量事件必须为0。PollSlot仍按激活原点的原网格计算跳槽，累计业务计数不变。配置激活重置游标，取消/旧配置结果不伪造新采样。

`NG_AuditEvent`保留Decision/Reason，在现有填充区增加：

| 字段 | 编码与上限 |
|---|---|
| DecisionFlags BYTE | 位0事实发布；位1平台；位2当前有效；位3延迟精确；位4版本差精确；位5报告事实精确；位6质量事件原点编码 |
| DecisionRevisionDelta USINT | 当前版本减采集版本，0～255；版本倒退或超界不设位4 |
| DecisionDelayLo UINT / DecisionDelayHi USINT | 24位毫秒延迟，0～16777215；倒退或超界不设位3 |
| ReportSkipped USINT | 普通物理事件0～254个漏报告槽；255未知、不截断为有效数字 |

质量状态事件若在决策时重置报告时基，策略使用源游标当时的NextDue。位6置位后，ReportSkipped改为**带类型标记的原点偏移编码**，不是漏槽数：`offsetSlots=ReportSkipped-127`，范围[-127,127]；原点为`O + (floor((captureCompleted-O)/pollInterval)+offsetSlots)×pollInterval`。O取该点首次激活的UNKNOWN原点。质量事件本身漏报告槽为0，跨代际原点不靠猜测。超界编码255使位5无效。该编码没有修改Event的名义槽或采集原点。

`AuditFactsComplete`与已有`EvidenceComplete`/业务`AccountingComplete`分开。编码越界仅使新事实不完整，不停止正常交付、不清unknown、不把业务数据判丢失。解码要求位0/3/4/5齐全且所有整数字段/安全范围正确。完整发布将Decision放在最后，禁止二次改写同一终态；导出须在读取前后核对boot、sampleSeq、Decision及环界，未决定/正在变化的记录不可确认。

## 独立验证范围

`Hub-Backend/tools/phase2/native_audit_facts.py`不导入Agent或PLC产品代码。`native_event_cohort.py`先核验启动前缀/字典/配置及完整捕获身份，再结合审计v2：

- 使用真实决策快照重新判定当前资格，覆盖“采集时有效、决策时失效/换代”的TIME_INVALID；不能再仅凭采集Flags认定应入队。
- 在冻结cyclic、poll==report配置下，从首次UNKNOWN激活原点和相邻已完成物理名义槽独立数漏轮询，与PollSkippedBefore逐项比较；按真实决策epoch独立重算报告漏槽。
- 固定源分母N，尾阶段继续验证原始事实/混合批次，N之外的计数单列，不扩大源分母。
- **只证明已完成物理结果前缀的历史空槽，以及该前缀的报告决策**。尚未完成的读请求、静默尾界、取消/配置切换外的区间另列，不将`trailingUncompletedPollWindowProven=false`或全局UNKNOWN改为正常长测零漏槽。重配置和其他reportMode仍需各自场景。

旧v1无这些字段，输出保持`decisionTimeClockSeparatelyAttested=false`、`missedSlotsIndependentlyVerified=false`。实测旧boot71原始日志的1782/1082/700及原始关联不变，新事实状态仍为LEGACY_UNATTESTED。没有向旧日志补造时间事实。
