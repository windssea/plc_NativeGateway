# Hub、Python IoT、原生 PLC 协同实施计划

2026-10-27，按本次产品目标重新整理。**当前执行入口为[主线开发与联调计划](三方主线开发与联调计划.md)（MAINLINE/1）**，其中逐项核查阶段0～3、原21项C/H/I/P任务、7项T任务、8项J里程碑及16项A验收要求。本页只保留总览，避免多个文件各写一套“下一步”。

## 产品分工

| 系统 | 用户要得到的能力 |
|---|---|
| Hub（前端和后端） | 管理网关/点表、下发配置并看到应用结果、查看状态、实时值与历史数据 |
| Python IoT | 接收配置、自动对时、稳定采集上传、持久Outbox重试及软件恢复 |
| 原生PLC | 接收配置、自动对时、稳定采集上传、重启后恢复业务；未上传历史跨重启保留属于文件持久化能力 |

## 当前顺序

1. 锁定运行版本和两类网关对象，在真实Hub前后端分别走通配置发布/应用→自动对时→采集上传→最新值/历史查询。
2. 验证各网关重连、软件重启及具体宿主的自动恢复；复用已有I06/T04证据，按实际差异补缺项。
3. 同一候选先做30分钟正常主流程观察，再安排24小时连续运行；不为每个检查点反复换工程。
4. 基础链路稳定后，补齐必要运行状态展示、部署权限/单时间权威及原生文件日志等可靠性工作。
5. P06和完整恢复容量/性能专项后置；MCP只是编译、下载和调试工具，M14不再前置整个联调。
