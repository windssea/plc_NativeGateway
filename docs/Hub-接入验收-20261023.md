PLC 2152 上最终运行 `native-0.3.1`，采集、JSON 配置处理、持久化、组批、业务 ACK 全部为 Engineer 原生 IEC/ST，Web HMI 使用 Engineer 原生页面。PC 的 Python/Java 进程用于 mock、API 测试、只读 MQTT 观察和资源取证，不在控制器上作为采集 Agent 运行。

## 对齐的通信行为

Topic 前缀为 `iot/v1/gateway/NG-HUB-2152-01/`，schemaVersion=1。控制器订阅 config/set、config/patch、data/ack；发布 config/get、config/ack、config/patch/ack、heartbeat、status、device/status、data。

Hub 实际使用 devicePatchV1：首次发布 baseConfigVersion=0、baseMessageId=null；后续补丁携带上一活动版本和 messageId。原始发布字节及 SHA256 用于幂等回放。修改周期通过 replace 操作携带完整设备点表，删点也以 replace 更新完整点表，删除整台设备使用 remove。

数据按点位到期、变化模式决定是否上报，再跨设备组批。最终版本每批最多 64 点且受约 12KB 值区预算限制，配置上限更小时提前分包；初期原生版本为 32 点。一次发布不保证包含全部设备，也不固定每台设备一包。Hub 为点位生成 `p-<variableId>`，为设备生成 `d-<deviceId>`；原生端使用这些发布身份，查询时由 Hub 映射回业务变量和设备。

传输层 QoS 1 的 PUBACK 不等于入库。仅严格校验过的 STORED 释放批次；暂时拒绝延后 60 秒，永久拒绝保留 RAM 死信。发送窗口最多 8 批，首次等待 30 秒，重试后等待 60 秒。报文重发保留原 ID 和原始字节，Hub 按既有收据机制去重。发送状态使用锁定的批次 ID，避免快速 STORED 早于 PublishDone 时污染已复用的队列槽。

## 管理模式与重启身份

`HUB_MANAGED` 是主模式：HMI 保留设备/点位列表、详情、诊断和 MQTT 维护，本地保存设备、保存点位、删除、周期应用和总应用被 PLC 程序阻止。按钮隐藏只是界面提示，程序侧也校验。`STANDALONE` 保留本地草稿编辑，切换模式需同时更换 Gateway ID；更换身份清空旧活动点表并重新等待配置。

v3 双槽文件保存配置、broker、管理模式、重放历史和 BootCounter。没有有效 v3 时尝试迁移 v2/v1。每次启动先提交递增计数，再连接 MQTT。网关摘要区分不同 Gateway ID，启动计数区分重启，sequence 区分当前启动的数据批次。数据 ID 不依赖 RTC。

Engineer 写入 PC 本地系统时间后，本次 UtcOffsetMinutes=480；MQTT 报文时间与 PC 对齐约 1 秒内。Hub 会检查控制消息的新鲜度，不能用固定的几十秒补偿代替时钟维护。

## 本次发现和修复

1. Hub 发布补丁前清除 retained config/set，会出现零字节消息。IIoT 5.3 对它返回 diagnostic 10 / `Null message received`；原处理会断开连接并丢掉后续补丁。当前仅忽略这一特定空消息返回，其他接收故障仍重连，真实连接丢失仍由 IsConnected 检查。
2. 新增诊断拼接和直接 LEFT 截取触发 MSG_ONL0156。使用 Engineer 字符串错误暂停定位，移除长诊断拼接，长 token 使用有界复制并记录实际长度。JSON 常驻 token 保持 256 字节，诊断路径最大 512 字节仍按原长度校验。最终运行须检查新增日志，而非靠清空历史日志证明修复。
3. 原先 5 秒重发在 Hub 开发入库延迟时放大积压，已改为 IoT 同等的 8 批窗口、30/60 秒等待，并修复早到 ACK 的槽位竞态。
4. 大批量 Hub 草稿写入与遥测入库并发时，10:59:21 出现 PostgreSQL deadlock，涉及 `biz_iot_gateway ... FOR UPDATE`。这是实际失败，保留 `deadlock-evidence.txt`。本轮暂停 PLC 并重启自己启动的本机 Hub 进程清理调试积压，分阶段准备草稿；没有修改后端锁顺序，此并发问题仍需单独回归/修复。后续顺序步骤通过不能抹去这次异常。

## 交付边界

- 配置可持久化；遥测仍为 16 批 RAM，未交付断电数据补发。背压期间继续采样并合并最新值，不保留所有中间变化。
- 供应商库 Will payload 只有 80 字节，完整 IoT 遗嘱容纳不下，当前未启用；Hub 通过心跳超时离线。
- 原生上限为 50 台、共享 320 点、每台 32 点，入站配置 131071 字节，只支持 Modbus TCP IPv4。IEC 字符串按字节有界，多字节长名称须考虑原生容量。
- 原 v104 长测只有效观察 2330.6 秒，109416 个 GOOD 值，无 schema/错误值；保留 HMI 短暂不可用事件。不是 8 小时通过。
- 本次软件维护重启与短测不能替代物理断电写盘故障、长期断网、TLS、真实电表和长期泄漏测试。
