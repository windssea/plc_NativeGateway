## 实现

- [NG_CaptureTypes.dt](../src/NG_CaptureTypes.dt)：72 字节紧凑事件、28800 条固定池、512 条入口、槽位状态/代际、四个引用计数配置槽、64 条缺口及批次引用/tombstone 空间。池与相关元数据均为 RAM，不加入 NG_Durable/NG_File，配置 v4 文件格式不变。
- [NG_Capture](../src/NG_Capture.st)：在最终结果/状态边界分配运行期 sampleSeq，冻结工程值、质量、完成单调时刻、物理名义槽、配置槽/代际、采样代际及原始时间。配置字典保留 gateway/captureBootId 和完整原配置，引用未释放时不复用。入口满仍推进捕获序号，精确增加 captureOverflow/undecidedLost，保留原入口，不覆盖历史；缺口明细环满置 detailTruncated，累计数不清零。
- [NG_ConfigSlot](../src/NG_ConfigSlot.st)、[NG_SameConfig](../src/NG_SameConfig.st)：保存配置前预留槽，落盘成功后才切换活动槽；保存失败撤销预留。第五个仍被引用的配置拒绝新提交，保留当前配置和旧事件。同配置重复应用不重建 UNKNOWN/采样网格。配置代际和 sampleSeq 耗尽均关闭采集，不回绕。
- [NG_Modbus](../src/NG_Modbus.st)、[NG_SourceResult](../src/NG_SourceResult.st)、[NG_SourceState](../src/NG_SourceState.st)：GOOD、最终 BAD、连接失败影响的各点均进入入口；内部协议重试不产生中间事件。UNKNOWN 在启用后一次创建；STALE 按最近最终物理结果的单调活性判断，在阈值处一次创建，同扫描先处理物理结果。持续 BAD 不被最近 GOOD 年龄覆盖。非 GOOD 事件无数值；缩放后非有限 GOOD 转 BAD_DECODE，不二次缩放。
- [NG_PollSlot](../src/NG_PollSlot.st)：保留启用时建立的名义网格，延迟执行取当前最后到期槽，跳过的槽逐点增加 missedPollCycles，不集中补做、不把 UTC 当调度依据。完成时刻不移动网格。读取保存配置/采样代际；配置提交或停用撤销在途读取，记 CancelledReadsTotal/VERSION_DISCARD，不虚构尚未完成的物理事件。旧结果不能修改新配置的入口和视图。
- [Main](../src/Main.st)：接入 50 个采集块及配置预留/提交顺序；修正 20 天 TON 翻转时先累加 epoch 造成单调时间先跳进再回退的问题。该修正未执行连续 20 天实测。原旧 latest 报告/16 槽发送路径仍待 P03/P04 替换；新增入口当前没有正常资格消费器，持续运行会达到 512 条并明确拒绝，不能部署为阶段 1 完整补传版本。

需要修改状态的辅助单元使用 FUNCTION_BLOCK 的 VAR_IN_OUT。FUNCTION 不支持该接口的 12 个错误已消除；Current 枚举重名警告及冗余 UDINT 转换亦已修正。最终测试项目只保留可达的采集辅助块，不包含 MQTT/存储/物理 I/O 调用，所有断言在 PLC 中执行。

## 时间边界

当前只启用 SYSTEM_RTC_COMPAT_UNVERIFIED。CapturedUtcMs 与 Flags 一起解释：bit 0 为原始时间存在，bit 1 为平台可信，bit 2 为物理名义槽存在，bit 3 为系统 RTC 来源。当前 bit 1 始终为 0，clockRevision 为兼容路径的 0；RTC 无效时 bit 0 清零，捕获后不回填。对外等价快照的可信 utcMs/timeValid 仍为 null/false；原始 RTC 只能映射到 systemUtcMs。QUALITY_STATE 的名义物理槽为 null。相同物理 UTC 保留不同 sampleSeq，仅计相邻物理结果时间重复，状态事件不打断比较。

这不是 MQTT 授时、时间失效令牌/平台有效代际、跨重启可信年龄或 ACK 时间门槛的实现。记录已预留相关修订/代际，完整 TimeProvider 仍在阶段 2 接入，不能据本轮结果放行 A02～A05/A13。

## P01 资源门槛

最终 AXC F 2152 实机 SIZEOF 见 [plc-final-test-result.json](../tests/validation/p01-p02/plc-final-test-result.json)。

| 项目 | 最终值 / 预算口径 |
|---|---|
| 单条事件 / 固定记录池 | 72 B / 28800 条；250 点下限 22500、320 点同周期下限 28800 均满足布局容量 |
| Buffer 主体 | 2933480 B；含记录、free stack、槽位状态/代际、入口、四份配置、游标、缺口及预留引用/tombstone |
| 发送与临时区 | 16 份 NG_Packet、Samples、Values/Item/TxPayload、空 Packet 和局部 point/sample、完整 Tx/Rx 各 262144 B 均计入，不只算历史池 |
| MQTT 固定状态预留 | 16384 B；编译元数据递归核对其状态上界，指针计入但不重复计算外部 Tx/Rx |
| SDK payload/封套副本预留 | 135680 B = 8 × (16384 + 512 + 64)，按最多八份保守预留；Client 自身 QoS 在途仍为 4，bufferedMessages=0 |
| 新增 FB 状态与调用暂存预留 | 65536 B；覆盖 50 个采集器的新增辅助实例及配置比较/选择、栈暂存，另以编译元数据核对实例上界 |
| 总布局及显式副本预算 | **4030279 B < 4194304 B**，余量 **164025 B** |

第一次 80 B/32768 条预检的 3933647 B 未包含完整共享收发区及额外副本预留，仅保留为初始证据，不作为最终门槛。最终压紧事件并把实际配额固定为 28800，没有降低 poll/report 频率。不能再用“最大可到 32768”代表当前可用容量。P03/P04 后续新增结构必须在本预算内复核，不能消耗未计入的隐含池。

4 MiB 是本缓冲的 IEC 结构、明确副本与状态预留核算。供应商原生 SDK 的其他私有堆、网络栈及整个控制器/进程内存不是可由 SIZEOF 证明的量，须在 P06 测实际高水位。布局通过不表示已证明 300 秒覆盖、mu>lambda、每扫描新增 <=1 ms 或控制器资源充足。
